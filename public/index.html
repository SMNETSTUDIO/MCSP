RCON 未启用
开启后控制台命令优先走 RCON:能拿到命令的实际输出(stdin 只能发不能收), 服务端主线程卡死时也是独立通道。任何一步不通都会自动回落 stdin,不会因此发不出命令。
「一键开启」会在 server.properties 里写入 enable-rcon=true、 分配端口(默认 server-port + 10)并生成随机密码,需要重启实例生效。 密码只在面板内显示;RCON 端口不要暴露到公网。

系统设置
「开放注册」是总开关:关闭后即使 OAuth 配置里开着「自动建号」,新身份也无法注册(已有账号不受影响)。 公告修改后立即对所有用户生效;用户关掉的公告再次编辑后会重新弹出。
备份保留策略在每次备份成功后执行,两个条件取并集(任一超限即删)。最新的一份永远保留, 所以把天数调得很短也不会把刚做完的备份删掉。不影响手动删除,也不会去动历史遗留的备份 —— 它们会在下次备份时一并按策略清理。
强制两步验证默认关闭,会连你自己一起挡住:没配 TOTP 的账号除了「账号安全」页什么都打不开。 你自己没启用 TOTP 时开关是禁用的(后端同样会拒绝),因为开启后系统设置页本身也会被拦, 没法再从面板关掉 —— 那就只能去改磁盘上的 JSON 了。同理,策略开着时不允许关闭自己的 TOTP, 要关请先关策略。
API Token 不受此开关影响,否则开启的瞬间所有脚本都会断;签发新 Token 需要网页会话, 所以没配 2FA 的人也绕不过去。
崩溃阈值按实例类型调:重度模组服启动慢、崩得勤,3 次/10 分钟容易误判成"重启风暴"而停手。
异地备份 未启用
备份现在和被备份的东西在同一块盘上 —— 盘坏了、机器被回收,备份跟着一起没。 开启后每次备份成功都会把包在后台传一份到异地,按 <实例 ID>/<文件名> 分目录。
上传失败不影响本地备份:本地那份已经做完了,传不上去只会告警。 反过来也一样——异地上传不会拖慢备份接口,几十 GB 走慢线路可能要几十分钟。
密钥保存后不再回显明文(显示为 ••••••••),原样提交表示不修改。 「测试连通性」会用已保存的配置真传一个探针文件上去 —— 只 ping 通说明不了权限和桶名对不对。
面板配置备份 面板自身的配置,不含世界与插件
打包 settings.json / users.json / instances.json / tasks.json / oauth.json,用于换机器或误删恢复。 不含会话、登录失败计数与审计日志(一次性状态,搬过去反而有害), 也不含实例目录和备份包本身 —— 那是 GB 级的数据,把 instances/ 目录一起拷过去才能真正接上。
导出文件里有口令哈希、TOTP 密钥和 API Token 摘要,等同于凭据库,请按密钥的规格保管。 导入会先把现有文件另存为 .bak-<时间戳>,写完需要重启面板才生效。
